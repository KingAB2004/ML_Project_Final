# planstudy.md: a study guide to COCCON_NEW

This guide explains the whole project in the order you should learn it: what problem it solves, how the data
is built, how the model is trained and tested, which statistics back each claim, and why each design choice
was made. Every section points to the file that does the work, so you can read the code next to the text.

Suggested reading order: sections 1-3 (the big picture), 4 (dataset), 5 (fine-tuning), 6-8 (the three
enhancements built on top), 9 (evaluation and statistics), 10 (the analyses beyond the SOP), 11 (the scaling
study now running), 12 (infrastructure and schedule), 13 (results so far), 14 (likely viva questions).

---

## 1. The problem in one paragraph

People in distress often do not ask for help, and they resist direct questions ("reactance": pushing back
when you feel your autonomy is threatened). Most AI support systems are reactive: they wait for the user to
state a problem. COCOON (EMNLP 2025, "Look Beyond Feeling") built a *proactive* supporter that starts the
conversation and infers the hidden need behind a surface feeling (Feeling -> Need -> Response) without
interrogating. Our SOP (`modified_SOP_12340340_12340370.pdf`) extends COCOON in four ways, in English, with
open models only, on one 12 GB GPU.

## 2. What COCOON did, and the three gaps we attack

COCOON: Chinese corpus; profiles fully generated by an LLM; one session per user; one model does the
analysis, the strategy and the reply in a single pass; resistance is checked only in aggregate (by steering a
global "how many questions" ratio). Neither its corpus nor its construction pipeline is released.

| Gap (SOP Fig. 1) | Our fix | Code |
|---|---|---|
| 1. Single session, no memory | E1 multi-session corpus with time gaps + E4 need-state memory | `src/sessions.py`, `src/memory.py` |
| 2. Monolithic inference, no point to inspect | E2 four agents + grounding contract + conformal critic gate | `src/agents.py`, `src/grounding.py`, `src/conformal.py` |
| 3. No turn-level resistance check | E3 Intrusiveness Penalty (IP) and Psychological Reactance Index (PRI) | `src/metrics.py`, `src/counterfactual.py` |

Plus fine-tuning (SOP III-E): the supporter is an open model fine-tuned with QLoRA on our corpus, with the
annotation ablation (with vs without thoughts).

## 3. The big picture: one flow, many stages

```
EmpatheticDialogues situations
  -> seeds.py        screen + stratify by problem type                     data/seeds/seeds.jsonl
  -> profiles.py     need chain (3 nodes) + hidden persona + resistance     data/profiles/*.jsonl
  -> dialogue.py     session 1: proactive supporter vs resistant seeker     data/corpus/sessions.jsonl
  -> sessions.py     sessions 2-4 after sampled time gaps, profile evolves  (same file)
  -> filter.py       structural checks + AELS judge                         sessions_filtered.jsonl
  -> annotate.py     Analysis + Strategy label per supporter turn           sessions_annotated.jsonl
  -> build_sft.py    training examples, two arms                            data/sft/{with,wo}_thoughts_*.jsonl
  -> train.py        QLoRA fine-tune                                        runs/<id>/adapter_<arm>/
  -> evaluate.py     roll out each arm on held-out test profiles            runs/<id>/dialogues/<arm>.jsonl
  -> calibrate.py    fit the conformal gate on calibration profiles         runs/<id>/conformal/calibration.json
  -> metrics.py      judge scores: Success, AELS, CRS, RAC, basic, IP, PRI  runs/<id>/scores/<arm>/
  -> counterfactual.py  causal PRI by replaying the seeker                  runs/<id>/scores/<arm>/pri_summary.json
  -> report.py       tables, paired bootstrap CIs, Holm correction          runs/<id>/results_*.md
```
`scripts/run_all.py` runs this plan in order and records finished steps in `pipeline_state.json`, so a
crashed run resumes where it stopped.

### Design rules (`PLAN.md` Sec. 0, enforced by code)
1. **Every stage reads files and writes files.** If annotation breaks, only annotation reruns.
2. **One model on the GPU at a time.** `llm.LLM` raises `ResidencyError` if a second model is loaded. The four
   agents, the seeker simulator and the corpus generator are *roles* (different prompts and temperatures)
   served by one resident model through `LLM.view(role)`. Why: 12 GB cannot hold several 7B models.
3. **Structured output augments, never replaces, raw history.** Every agent and judge sees the verbatim turns.
4. **Nothing enters memory ungrounded.** Every memory write needs a verbatim user quote (`grounding.validate_span`).
5. **Resumable.** Every record has a deterministic id; a stage skips ids already written.
6. **No proprietary API.** There is no code path that can call one.

### The two models (`configs/models.yaml`)
| Role | Model | Why |
|---|---|---|
| Supporter, seeker simulator, 4 agents, corpus generator | Qwen2.5-7B-Instruct (Ollama q4 for generation; HF nf4 for training) | strong open 7B, fits the card |
| Judge and annotator | Mistral-Nemo-12B-Instruct (Ollama q4_K_M) | a **different family**: PRI scores the seeker's turn, so a judge from the simulator's family would grade its own output (SOP control 2; `judge.assert_judge_separate` refuses to run otherwise) |

### The LLM layer (`src/llm.py`)
Backends: `echo` (deterministic stub for tests), `ollama` (generation and judging, parallel requests),
`transformers` (needed whenever an adapter is loaded, since Ollama cannot load a LoRA adapter), `vllm`
(optional). Every call is cached on disk, keyed by role, model, adapter, messages and sampling settings, so
rerunning a stage is free. Note: the key does **not** include the backend, so never run the real pipeline with
`--backend echo` in a real checkout (stub replies would be replayed later).

## 4. Enhancement 1: the dataset (E1)

### 4.1 Seeds (`src/seeds.py`)
EmpatheticDialogues situations are human-written narratives, not help requests (SOP III-A). Each candidate
is classified into an ESConv problem type (stratification key) and screened by the judge: "can this support a
three-step need chain?". The full run screened 2,000 and released 1,000 (85.5 % passed). The SOP's fallback
(fully LLM-synthesized profiles) exists as `--route synthetic`; we used the seeded route.

### 4.2 Profiles (`src/profiles.py`)
- **Need chain**: depth 0 surface feeling -> depth 1 intermediate need -> depth 2 terminal (hidden) need.
  Validators enforce exactly 3 nodes and non-triviality (depth 2 must not paraphrase depth 0; similarity
  ceiling 0.75). Why: if the hidden need is obvious, Success Rate means nothing.
- **Persona**: a surface layer (style, topics they volunteer) and a hidden layer (terminal need, resistance
  level, disclosure triggers and blockers). Triggers (validation, accurate reflection, patience) lower
  resistance; blockers (premature advice, naming an undisclosed feeling, repeated questioning) raise it. This
  makes resistance *respond* to the supporter; otherwise nothing the supporter does would matter.
- **Resistance strata** low:medium:high = 1:2:1, so every arm sees all three levels.
- **Splits by profile** (never by turn): 720 train / 100 val / 100 test / 80 calibration. A profile never
  appears in two splits, so test results are not inflated by memorised users.

### 4.3 Session 1 (`src/dialogue.py`)
The supporter opens (from a pool of natural openers: the seeker did not ask for help). Listening phase
(reflect, validate, probe gently, no advice), then suggestion phase. The simulator and supporter each keep a
mirrored message list; the judge reads a flat transcript. 8-12 turns per side.

### 4.4 Linked sessions (`src/sessions.py`)
2-4 sessions per profile, separated by gaps drawn log-uniform from 1 to 56 days (log-uniform gives both
"next day" and "six weeks later", which creates real recency-vs-relevance tension). Between sessions the
profile advances by a rule-based transition: resolved (0.35), intensified (0.45), displaced by a new concern
(0.20). The gap is stated in the next session's context ("it's been about three weeks"). Chain node ids stay
stable so memory can be scored across sessions.

### 4.5 Filter (`src/filter.py`)
Cheap structural checks first (turn count, alternating roles, repetition, English, crisis terms, and
**leakage**: the seeker must not recite its hidden need in its first 2 turns), then the AELS judge (Active-
Empathic Listening Scale, keep if mean >= 5 and no item < 3). Filtering is per profile: if session 2 fails,
the later sessions of that profile are dropped too (they would be a broken time sequence).

### 4.6 Annotation (`src/annotate.py`)
For every supporter turn, the judge writes a free-form **Analysis** (what is going on for the seeker) and
**Strategy** (what this move does). Free-form content-level labels, not a fixed taxonomy, because that is
COCOON's claimed advantage over ESConv/ExTES. A degeneracy check clusters the strategy phrases (top-3
clusters must not cover > 80 %). Full run: 21,354 unique phrases in 19,078 clusters, top-3 share 1 %.

### 4.7 The 1000-profile corpus (finished 4 Oct 08:15)
| Stage | Result |
|---|---|
| Seeds | 1,000 of 2,000 screened |
| Profiles | 720 / 100 / 100 / 80 |
| Sessions generated | 820 first + 1,673 follow-up = 2,493 |
| Filter | 2,369 kept, 66 rejected, 58 tails dropped |
| Annotated supporter turns | 21,429 |
| SFT examples per arm | 18,821 train / 2,608 val |

## 5. Fine-tuning (SOP III-E)

### 5.1 The training examples (`src/build_sft.py`)
One example per supporter turn. Input = system prompt + dialogue so far (+ time gap and memory brief for
later sessions), in exactly the format used at inference. Two arms from the same turns:
- `with_thoughts`: target = `<analysis>...</analysis> <strategy>...</strategy> <response>...</response>`
- `wo_thoughts`: target = `<response>...</response>` only

Why: the SOP says reasoning should be **learned, not prompted**; the wo_thoughts arm is the reproduction check
against COCOON's published annotation ablation. Only the `<response>` text is ever shown to the seeker.

### 5.2 LoRA vs QLoRA: we use QLoRA (`src/train.py`)
- **LoRA**: freeze the base weights W and learn a low-rank update dW = (alpha/r) B A, with B (out x r) and
  A (r x in). With r = 32 only ~1 % of the parameters train (80.7 M for the 7B).
- **QLoRA** = LoRA on top of a base stored in **4-bit NF4** (NormalFloat-4, double quantization), computed in
  bf16, with a paged 8-bit AdamW optimizer and gradient checkpointing.
- **Why QLoRA**: the 7B in bf16 needs ~15 GB just for weights; the RTX 3060 has 12 GB. In NF4 the weights take
  ~5 GB, leaving room for activations at sequence length 2048. The SOP commits to "4-bit quantized low-rank
  adapters, single GPU". For the scaling study the 0.5B and 3B use the **same** QLoRA recipe even though
  plain LoRA would fit for 0.5B: size must be the only thing that changes between points.
- Settings (`configs/default.yaml` -> `train:`): r 32, alpha 64, dropout 0.05, all attention and MLP
  projections, seq 2048, micro-batch 1 x accumulation 16 (effective batch 16), lr 2e-4 cosine, warmup 3 %,
  3 epochs, loss on target tokens only, best-validation checkpoint kept.
- Two fixes worth knowing (`BUGS.md`): `prepare_model_for_kbit_training` upcasts embeddings to fp32 and ran out
  of memory, so it is not used; the evaluation batch defaulted to 8 and ran out of memory at the end of
  epoch 1 (B50), so it is set to the training micro-batch.
- Every run now saves `train_summary_<arm>.json` with the full loss history (`log_history`), the best
  checkpoint and the best validation loss; every epoch checkpoint keeps `trainer_state.json`.

## 6. Enhancement 2: multi-agent pipeline and the conformal gate (E2)

### 6.1 Four agents, one model (`src/agents.py`)
1. **Analyzer**: reads the history (+ memory brief), outputs emotional state, implicit needs, resistance, open
   questions; every inference needs a supporting quote and a confidence.
2. **Strategist**: picks a content-level move and a target depth ("ladder rung" L0-L3, `src/pacing.py`). If the
   Analyzer's confidence is below 0.45, only exploratory rungs L0-L1 are allowed: uncertainty produces
   gentleness instead of confident overreach.
3. **Generator**: writes the reply at or below the allowed rung.
4. **Critic**: scores the draft on the IP rubric, runs the grounding checks, computes a nonconformity score s,
   and decides: release, revise (up to 2 times), or fall back to a plain reflective statement.
Run sequentially (one model on the card). The SOP does not claim decomposition is new; the contract and the
gate are the contribution.

### 6.2 Grounding contract (`src/grounding.py`)
Each claim in a draft gets a category with a weight. The decisive one, with no counterpart in factual
grounding: **denied_inference**, re-proposing something the seeker already denied (the signature of
premature interpretation). Others: unsupported state attribution, fabricated fact, overreaching depth,
unsolicited advice, stale reference. Checks are mechanical where possible (quote in text, memory status).

### 6.3 The conformal risk gate (`src/conformal.py`, `src/calibrate.py`)
Instead of a hand-tuned threshold, the SOP asks for a **distribution-free guarantee**:
- A turn is a *violation* if the judge's IP (normalised 0-1) exceeds tau = 0.2.
- The gate releases a draft if s <= lambda. Risk R(lambda) = fraction of turns released *and* violating;
  R grows with lambda.
- On 300 calibration turns (calibration profiles only), compute an upper confidence bound on R(lambda) for each
  lambda (Hoeffding-Bentkus bound, confidence 1 - delta, delta = 0.1) and pick the **largest** lambda whose
  bound is <= alpha = 0.1 (largest = least needless blocking). Result: lambda_hat = 0.125.
- Guarantee: with probability >= 0.9, the violation rate among released turns is <= 0.1 **on turns
  exchangeable with the calibration turns** (same generator, same profile distribution). Out of distribution
  it is reported as a measured rate, never as a guarantee; `report.py` refuses the word "guarantee" there.
- Why tau = 0.2 not 0.5: at 0.5 no calibration turn was a violation (max judge IP 0.357), so the gate was inert.

### 6.4 The 2 x 2 ablation
| | ungated | gated |
|---|---|---|
| monolithic listener | cell A | cell B |
| decomposed agents | cell C | cell D (full system) |
All on the same test profiles, paired. `report.py` computes both main effects and the interaction, so "does
the gate or the decomposition pay?" is read off the table.

## 7. Enhancement 3: turn-level metrics (E3)

- **IP** (`prompts/metric_ip.md`): 7 judge items (1-7) on each **supporter** turn: advice too early, asserting
  an unexpressed feeling, naming an unacknowledged need, pressing past reluctance, over-deep interpretation,
  ignoring a boundary, exposing rather than supportive. IP = (mean - 1) / 6. Higher is worse.
- **PRI** (`prompts/metric_pri.md`): 7 items on the **seeker's next turn**: anger (irritation, hostility),
  negative cognition (counter-arguing, dismissal, autonomy assertion), behaviour (deflection, withdrawal).
  Reactance as the conjunction of anger and negative cognition (Dillard & Shen 2005).
- **Counterfactual PRI** (`src/counterfactual.py`): treat each supporter turn as an intervention. Replay the
  seeker's reply N times after the real turn (r1) and after a neutral reflective control turn (r0), with the
  same seeds; PRI = mean(r1) - mean(r0) with a paired bootstrap CI. Positive = the move provoked resistance
  beyond what a neutral reflection would. 4 turns per dialogue (early, middle, middle, late).
- Three validity controls (SOP): resistance level hidden from the judge (recorded in `context_redactions`);
  judge from a different family; judge-human agreement on a stratified sample (`human_eval/sample.py`,
  `agreement.py`; the human ratings are still to be done).
- Other instruments: Success Rate (did the supporter identify the hidden need), AELS, Comforting Responses
  Scale (CRS), RAC, basic quality.

## 8. Enhancement 4: need-state memory (E4, `src/memory.py`)

Memory stores **beliefs about the need chain**, not facts. Each node: status (hypothesis / confirmed /
disconfirmed / resolved), supporting and contradicting quotes with timestamps, confidence. Rules:
confirm needs 2 spans incl. an explicit agreement; a denied inference becomes disconfirmed and **blocked from
re-proposal**; unconfirmed hypotheses decay with a 14-day half-life (confirmed/disconfirmed do not decay: a
tested link stays tested); a resurfacing concern is reinstated at half its confidence. Retrieval is a
question ("best current hypothesis, what is still untested, what is forbidden"), not similarity search.
Baselines in `src/baselines/`: no memory, running summary, dense retrieval, event-level memory.

## 9. Evaluation and statistics (`src/evaluate.py`, `src/report.py`)

- Arms (`configs/arms.yaml`): base_instruct, reactive_baseline, the 2x2 cells, calib_dec_ungated (only for gate
  calibration, on calibration profiles), sft_with_thoughts, sft_wo_thoughts.
- Every arm runs on the same 100 test profiles; scores are per profile, so comparisons are **paired**.
- CIs: bootstrap over profiles (the profile is the independent unit; turns of one profile are correlated).
- Many comparisons -> Holm correction. Every cell prints its n. Reports refuse to print a number without n.

## 11. The scaling study (running now)

Same QLoRA recipe, same 1000-profile SFT files, three sizes of Qwen2.5-Instruct: **0.5B and 3B** (laptop RTX
4060 8 GB) and **7B** (lab RTX 3060). N below = non-embedding parameters (0.36B, 2.77B, 6.53B), the count
scaling laws are fitted on (Kaplan et al. 2020). The 1.5B was dropped for time.

### Idea 1: scaling law and the thoughts interaction (`extra/scaling.py`, server: `scripts/scaling_eval.sh`)
- Validation loss vs N: fit L(N) = a N^-b by least squares in log-log space. With 3 sizes there is one
  residual degree of freedom, so the 95 % CI on b (bootstrap over validation profiles, using per-turn reply
  NLL from `pvi.py`) is the honest statement. L = a N^-b + c needs a 4th size and is not fitted.
- Test metrics: every adapter is rolled out on the 100 test profiles against **the same 7B seeker**. A smaller
  supporter is loaded beside the 7B base (`evaluate.py --supporter-base`, `llm.TransformersBackend`), so only
  the supporter changes. Without this, a 0.5B supporter would face a 0.5B seeker.
- Thoughts gain D(N) = metric(with) - metric(wo), paired over test profiles; interaction = slope of D against
  log10 N with a bootstrap CI. A negative slope on Success means the thoughts help small models more.
- Note: validation losses of the two arms are not comparable to each other (the with_thoughts target also
  contains the thoughts). Arms are compared on reply NLL and test metrics.

### Idea 2: pointwise V-information (`extra/pvi.py`, laptop)
PVI_i = log2 p_with(reply | context, thoughts) - log2 p_wo(reply | context), per validation turn
(Ethayarajh et al. 2022). The wo_thoughts adapter plays the "null input" model. Same reply tokens under both
(checked, mismatches skipped). Mean PVI = bits of usable information the gold thoughts carry about the reply.
PVI < 0 flags annotations that made the reply *less* predictable: the first labels to audit. Also by ladder
rung and against thought length.

### Idea 3: LoRA geometry (`extra/lora_geometry.py`, laptop)
For each adapted matrix dW = s B A, the singular values come from the r x r core (QR of B and A^T, then SVD),
never forming the full matrix. Reported: norm, stable rank, effective rank exp(H(sigma/sum sigma)) out of 32,
energy in the top 4 directions, where along the depth the update mass sits, and the subspace similarity
phi(k) = ||U_with^T U_wo||_F^2 / k between the two arms (Hu et al. 2021; random subspaces give ~k/d).
`--truncate` replaces every dW by its best rank-k approximation (Eckart-Young) and measures validation loss
for k = 0 (base), 1, 2, 4, 8, 16, 32: how much of rank 32 the task actually needs. Checked: at k = r it
reproduces the adapter's loss to 0.02 % (bf16 noise).

## 13. Results so far (v2 snapshot, 50-profile corpus, 40 test profiles: `results/v2/README.md`)

- The pipeline works end to end: 0 leaked hidden-need turns of 6,449.
- The gate does its job: IP drops 25-35 % (0.078 -> 0.059 monolithic, 0.095 -> 0.062 decomposed) for about
  0.02 Success. Decomposition alone adds nothing measurable: exactly the "where does safety come from"
  answer the SOP said it would report.
- Counterfactual PRI ~ 0 for every arm: no arm provokes more resistance than a neutral reflection.
- The fine-tuned 7B (with thoughts) matches the base on Success (0.392 vs 0.383) but is pushier (IP 0.103 vs
  0.082, observed PRI 0.272 vs 0.212). The 1000-profile run tests whether that holds with 16x the data.
- At n = 40 most differences sit inside their CIs; the 1000-profile run is where findings come from.

## 14. Questions you should be ready for

- *Why QLoRA?* 7B bf16 does not fit 12 GB; NF4 base + bf16 adapters does; same recipe at every size.
- *Why a different judge family?* PRI scores the simulator's turn; a same-family judge would grade itself.
- *What exactly does the conformal gate guarantee?* With probability >= 1 - delta, released-turn violation
  rate <= alpha, only for turns exchangeable with the calibration turns; out of distribution it is a measured
  rate. It needs no model assumptions, only exchangeability.
- *Why split by profile?* Turns of one user are correlated; splitting by turn leaks users into the test set.
- *Why bootstrap over profiles?* Same reason: the profile is the independent unit.
- *Why is counterfactual PRI better than observed PRI?* Observed resistance mixes pre-existing resistance with
  resistance the move caused; the seed-matched replay against a neutral control isolates the move's effect.
- *Why did you drop 1.5B / why only 3 sizes?* Time on the laptop GPU; three points give the direction and a
  CI on the exponent, not a precise law, and the report says so.
- *What is PVI telling you that the wo_thoughts ablation does not?* The ablation gives one aggregate number
  after generation; PVI says per turn how much the thoughts inform the reply, and finds the bad labels.
- *Is everything simulated?* Yes: seekers are simulated and scores are LLM-judged; the judge-human agreement
  study is the missing piece, and transfer to real people is out of scope.
